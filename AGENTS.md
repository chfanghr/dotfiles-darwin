# Agent Notes

## Repo Shape
- This is a Nix flake dotfiles repo using `flake-parts` with the dendritic pattern: `flake.nix` wires inputs, imports the auto-imported `./modules` tree via `import-tree`, and explicitly imports top-level entry modules.
- Files under `modules/` are top-level `flake-parts` modules. They should contribute lower-level modules/configurations through top-level options such as `flake.modules.darwin.common`, `flake.modules.homeManager.fanghr`, `flake.modules.nvf.common`, and `configurations.darwin`.
- Top-level non-dendritic entry modules live next to `flake.nix`: `flake.nix` defines the flake-parts `systems` option inline, and `pre-commit.nix` wires `git-hooks-nix` and the dev shell.
- Host entrypoints are `darwinConfigurations.{Dioscuri,Hera,Granicus}` from `modules/hosts/{Dioscuri,Hera,Granicus}.nix`; machine-specific declarations should stay in this subtree alone.
- `modules/configurations/darwin.nix` defines `configurations.darwin` with `deferredModule` and turns it into `flake.darwinConfigurations`.
- Shared custom options and helpers live in `modules/shared.nix` and are exposed as lower-level modules for Darwin and Home Manager. Host flags flow into nix-darwin and Home Manager via `my.shared.inheritable`.
- Darwin common configuration is merged into `flake.modules.darwin.common` from files under `modules/darwin/`, including Home Manager integration, Determinate Nix, user config, and common Darwin settings.
- User Home Manager config is merged into `flake.modules.homeManager.fanghr` from files under `modules/home/fanghr/`; the only configured user is `fanghr`.
- Neovim config is `flake.modules.nvf.common` from `modules/nvf/common.nix` and is exposed as `packages.<system>.nvim-common` from `modules/nvf/package.nix`.

## Commands
- Enter the dev shell with `nix develop`; `.envrc` also uses this flake.
- Run all repo checks with `nix flake check --no-write-lock-file`.
- Run hooks directly with `nix develop --command pre-commit run --all-files`.
- Format-check Nix with `nix develop --command alejandra --check .`; lint dead code with `nix develop --command deadnix --fail .`.
- Dry-run one host build with `nix build .#darwinConfigurations.<host>.system --dry-run --no-write-lock-file`, for example `Hera`.
- Apply a host only when explicitly asked: `darwin-rebuild switch --flake .#<host>`.

## Host Facts
- `Dioscuri`: `aarch64-darwin`, desktop, gaming rig.
- `Hera`: `aarch64-darwin`, desktop.
- `Granicus`: `x86_64-darwin`, slim; `ids.gids.nixbld = 30000`.
- `nix flake check` on Apple Silicon omits incompatible systems; `Granicus` may be omitted unless checking all systems from a compatible context.

## Gotchas
- `.pre-commit-config.yaml` is generated by `git-hooks.nix`; edit hooks in top-level `pre-commit.nix`, not the generated file.
- `modules/` is auto-imported by `import-tree`; move only dendritic flake-parts modules there. Keep entrypoint-style modules such as `pre-commit.nix` at the repo root and import them explicitly from `flake.nix`.
- `flake.modules.<class>` namespaces should stay flat where possible. Prefer merging many feature files into shared lower-level module names such as `flake.modules.darwin.common` and `flake.modules.homeManager.fanghr` instead of creating many named lower-level modules.
- If adding new files that Nix must evaluate before commit, use `git add -N <path>` so flakes can see them without staging content for commit.
- `nix fmt` is not configured despite a `formatter` output appearing in `nix flake show`; use Alejandra via the dev shell instead.
- Desktop hosts enable Homebrew with `onActivation.cleanup = "zap"`; switching can remove manually installed brews/casks.
- Apple Silicon hosts use Determinate Nix and enable the VM-based Linux builder; x86_64 Darwin falls back to the regular `nix` module.
- `modules/home/fanghr/packages.nix` filters packages through `supportedPackagesOnly`, so unsupported packages may be silently excluded by platform.
